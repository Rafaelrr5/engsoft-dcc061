🧪 Testes · 2 questões

O professor falou "se cair essa…" umas 5 vezes sobre a 34.

Pergunta Vai cair
34Preencha cobertura de comandos (Cmd) e branches (Brch). 
void f(int x, int y) {
  if (x > 0) {
    x = 2 * x;
    if (y > 0) {
      y = 2 * y;
    }
  }
}
4 comandos, 4 branches.
Conceito
Comandos = linhas executadas; branches = lados (V/F) de cada if percorridos.
Resposta Gabarito oficial
  • f(0,0): Cmd 25%, Brch 25% (só o 1º if, lado F).
  • f(1,1): Cmd 100%, Brch 50% (só lados V).
  • f(0,0) e f(1,1): Cmd 100%, Brch 75% (falta o F do 2º if).
Pergunta Mais provável
35Conceito A se nota ≥ 90. Código: if (nota > 90) return true; else return false; (a) Há bug? Quando vira falha? (b) Testes com 95 e 85: cobertura de comandos e branches?
Conceito
Defeito vs falha + valor de fronteira: 100% de cobertura não garante achar o bug.
Resposta Gabarito oficial
  • (a) Sim (> em vez de >=). Falha quando a nota é 90.
  • (b) Comandos = branches = 100% — e mesmo assim o bug passa.
Pergunta Reserva
28Por que testes são tanto verificação quanto validação? Qual tipo serve para verificar? E para validar?
Conceito
Verificação: "fiz certo?" (vs especificação). Validação: "fiz a coisa certa?" (vs o que o cliente quer).
Resposta Gabarito oficial
  • Depende da referência: especificação = verificação; cliente = validação.
  • Verificação: testar um método para ver se retorna o resultado especificado (teste de unidade).
  • Validação: teste funcional e de aceitação, ao lado do cliente.
Pergunta Reserva
31Defina e explique os 4 níveis de teste, com 1 exemplo de cada.
Conceito
Níveis de teste: do menor pedaço (unidade) até o cliente (aceitação).
Resposta Sem gabarito: montada pelos slides
  • Unidade: testa componente isolado (método/classe), feito pelo dev. Ex.: fatorial(3) == 6 no JUnit.
  • Integração: testa as interfaces/interações entre componentes. Ex.: pedido chama pagamento com os parâmetros certos.
  • Sistema: sistema inteiro vs requisitos (inclusive não funcionais), caixa-preta. Ex.: desempenho com 20.000 usuários.
  • Aceitação: usuário/cliente valida as necessidades do negócio (alfa/beta). Ex.: banco executa "DOC para terceiros".

🏛️ Arquitetura · 2 questões · 1 é sobre Arquitetura Limpa

Arquitetura Limpa: estude 14, 15 e 16 juntas (camadas → Regra de Dependência → Inversão de Controle). A segunda de arquitetura deve ser de microsserviços (10 ou 9, com gabarito oficial).

Pergunta Mais provável
14Explique as 4 camadas concêntricas da Arquitetura Limpa com 1 exemplo de sistema.
Conceito
Arquitetura Limpa: 4 círculos, do núcleo (negócio) para a borda (tecnologia).
Resposta Sem gabarito: montada pelos slides
  • Exemplo: sistema de matrícula.
  • 1. Entidades (núcleo): regras gerais — Aluno, Disciplina.
  • 2. Casos de Uso: regras do sistema — MatricularAluno (checa pré-requisitos).
  • 3. Adaptadores: mediam o externo — controller REST que devolve JSON.
  • 4. Frameworks externos (borda): banco de dados, UI, e-mail.
  • Dependências sempre apontam para dentro.
Pergunta Mais provável
15O que é Regra de Dependência em uma Arquitetura Limpa?
Conceito
Regra que protege o núcleo: de fora para dentro, nunca o contrário.
Resposta Sem gabarito: montada pelos slides
  • Classes de uma camada não conhecem nada de camadas mais externas (classe, função, variável).
  • Dependências apontam para dentro: Frameworks → Adaptadores → Casos de Uso → Entidades.
  • Mantém entidades e casos de uso livres de tecnologia.
Pergunta Mais provável
16O que é Inversão de Controle em uma Arquitetura Limpa?
Conceito
Inversão de controle: o núcleo define a interface; a camada de fora a implementa.
Resposta Sem gabarito: montada pelos slides
  • Usada quando um caso de uso precisa chamar uma classe mais externa sem violar a Regra de Dependência.
  • O caso de uso define uma interface na própria camada (ex.: EmailService); a classe externa (MailServiceImpl) implementa.
  • Em execução o fluxo vai para fora, mas no código a dependência aponta para dentro — daí "inversão".
Pergunta Mais provável
10Streaming detecta problemas em vídeos. #1: cada detector é um microsserviço que carrega o vídeo do storage. #2: detectores são módulos de um monolito, vídeo carregado 1 vez e compartilhado. Qual é mais escalável?
Conceito
Quando NÃO usar microsserviços: se dividir obriga a repetir trabalho caro (I/O).
Resposta Gabarito oficial
  • Arquitetura #2 (monolito).
  • Carrega o vídeo da memória secundária para a principal uma única vez; na #1 cada detector carrega de novo.
  • Economiza tempo de execução e custo de nuvem. (Caso real: Amazon Prime Video.)
Pergunta Mais provável
93 vantagens e 3 desvantagens de microsserviços.
Conceito
Trade-off: independência dos times vs custo de sistema distribuído.
Resposta Gabarito oficial
  • Vantagens: evolução independente (cada time com suas releases); escalar com granularidade fina; tecnologias diferentes; falhas parciais (cai um serviço, não tudo).
  • Desvantagem 1 — Complexidade: em vez de chamada de método, protocolo como HTTP/REST.
  • Desvantagem 2 — Latência: chamar outra máquina tem custo de comunicação.
  • Desvantagem 3 — Transações distribuídas: difícil garantir atomicidade com vários bancos.
Pergunta Reserva
13Para que servem as portas em uma Arquitetura Hexagonal?
Conceito
Porta = interface (contrato) entre domínio e mundo externo.
Resposta Sem gabarito: montada pelos slides
  • Por onde passa a comunicação entre domínio e mundo externo; independentes de tecnologia.
  • Portas de entrada: de fora para dentro (serviços providos, ex.: empréstimo).
  • Portas de saída: de dentro para fora (serviços requeridos, ex.: persistência).
  • Domínio só conhece a porta; o adaptador a implementa → domínio isolado.

📐 Princípios e padrões · 2 questões

Regra da cola: chamadas encadeadas a.b().c().d() = viola Demeter. A questão "de 7 alternativas, cada uma com um conceito" é a 26 (padrões).

Pergunta Mais provável
20Que princípio é violado por bib.getAcervo().getAreaConhecimento("ES").getLivros().find("ESM").getNumExemplares();? Que mudança fazer em Biblioteca?
Conceito
Lei de Demeter: "não fale com estranhos" — evite cadeias longas de chamadas.
Resposta Gabarito oficial
  • (a) Demeter: longa cadeia de chamadas de métodos.
  • (b) Criar em Biblioteca o método getNumExemplares: bib.getNumExemplares("ES", "ESM");
Pergunta Mais provável
23Que princípio é violado e como alterar? 
void imprimeDataContratacao(Funcionario func) {
  Date data = func.getDataContratacao();
  String msg = data.format();
  System.out.println(msg);
}
Conceito
Demeter: o método só chama métodos da própria classe, de parâmetros, de objetos que ele cria e de atributos.
Resposta Gabarito oficial
  • Viola Demeter: data não é parâmetro, nem atributo, nem criado ali — equivale a func.getDataContratacao().format().
  • Solução: receber a data como parâmetro e renomear: void imprimeData(Data data) { System.out.println(data.format()); }
Pergunta Mais provável
26Dê o nome dos padrões descritos em A a I.
Conceito
Padrões de projeto (Gang of Four): soluções prontas e com nome para problemas recorrentes.
Resposta Gabarito oficial
  • A. Interface unificada de alto nível → Fachada
  • B. Única instância, ponto único de acesso → Singleton
  • C. Converte interface → Adaptador
  • D. Criar família de objetos relacionados → Fábrica
  • E. Método que centraliza a criação → Método Fábrica Estático
  • F. Intermediário que controla acesso → Proxy
  • G. Parametrizar algoritmos → Strategy
  • H. Avisar outros de mudança de estado → Observador
  • I. Esqueleto na base, passos nas subclasses → Template Method
Pergunta Reserva
22Calculadora.isPrimo(n) vale para 0 ≤ n < 10000; a subclasse CalculadoraRapida só vale para 1000 ≤ n < 9000. Que princípio é violado?
Conceito
Substituição de Liskov: subclasse deve funcionar em qualquer lugar onde a classe pai funciona.
Resposta Gabarito oficial
  • Liskov. Por herança, CalculadoraRapida pode substituir Calculadora.
  • Mas a substituição falha: a subclasse aceita uma faixa de valores mais estreita. Ex.: o pai resolve 0 a 999, a filha não.
Pergunta Reserva
19Sempre que uma tarefa mexe nas classes A e B (arquivos diferentes), o programador move B para o arquivo de A. Que propriedade melhora? Qual piora?
Conceito
Acoplamento evolutivo (lógico): arquivos que mudam juntos. Coesão de arquivo: arquivo com uma responsabilidade.
Resposta Gabarito oficial
  • Melhora: diminui o acoplamento evolutivo (lógico) entre arquivos. Antes 2 arquivos mudavam, agora 1.
  • Piora: diminui a coesão do arquivo de A — mais responsabilidades, requisitos não relacionados no mesmo arquivo.
Pergunta Reserva
17Sistema de ~100 KLOC: proponha uma especificação com a pior coesão possível e o melhor acoplamento possível.
Conceito
Coesão = módulo faz uma coisa só (quer alta). Acoplamento = dependência entre módulos (quer baixo).
Resposta Gabarito oficial
  • Pior coesão: todas as 100 KLOC num único método main.
  • Esse caso tem acoplamento mínimo: só existe um método, não há outro para se acoplar.

✅ Qualidade · 1 questão

Nenhuma de qualidade tem gabarito oficial: respostas montadas pelos slides.

Pergunta Mais provável
4Aponte e defina as 5 métricas estáticas vistas em aula + mais 2 usadas atualmente.
Conceito
Métrica estática: medida tirada do código/documento sem executar o programa.
Resposta Sem gabarito: montada pelos slides
  • Fan-in/Fan-out: nº de funções que chamam X / que X chama.
  • Complexidade ciclomática: complexidade de controle (nº de decisões + 1).
  • Índice FOG: tamanho médio de palavras e frases de um documento (legibilidade).
  • Profundidade da árvore de herança: nº de níveis de herança.
  • Acoplamento entre classes: quantas classes usam métodos de outras.
  • Mais 2 (fora dos slides): LOC (linhas de código) e LCOM (falta de coesão entre métodos).
Pergunta Reserva
2O que é o Padrão CMMI no contexto de qualidade de software?
Conceito
CMMI (Capability Maturity Model Integration): modelo que mede a maturidade do processo de uma empresa em níveis.
Resposta Sem gabarito: montada pelos slides
  • Modelo de referência para avaliar o nível de maturidade dos processos da organização.
  • Reúne práticas genéricas e específicas de engenharia de sistemas, software e hardware.
  • 5 níveis: 1 Inicial, 2 Gerenciado, 3 Definido, 4 Quantitativamente Gerenciado, 5 Otimização.
Pergunta Reserva
3Por que o modelo brasileiro MPS.Br é compatível com o padrão CMMI?
Conceito
MPS.Br: versão brasileira de modelo de maturidade (Softex), com degraus menores para empresas brasileiras.
Resposta Sem gabarito: montada pelos slides
  • Mesma base normativa: ISO/IEC 12207 e ISO/IEC 15504; mesmo objetivo: maturidade do processo.
  • Seus 7 níveis (G a A) se mapeiam nos do CMMI: G-F ≈ 2; E-D-C ≈ 3; B ≈ 4; A ≈ 5.
  • Degraus menores = mais acessível a pequenas empresas, mas equivalente ao CMMI.
